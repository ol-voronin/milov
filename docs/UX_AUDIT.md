# UX/UI аудит сайту та рекомендації

**Дата:** 27.07.2026 · **Еталони:** портал Дія (diia.gov.ua), Diia Design System,
GOV.UK Design System, практики NN/g для кризових аудиторій.
**Статус:** рекомендації ДО впровадження — нічого ще не виправлено.

---

## 1. Що робить Дія добре і що з цього варто запозичити

Аналіз diia.gov.ua (27.07.2026) показує п'ять патернів, релевантних нашому сайту:

**1.1. «Життєві події та ситуації» від першої особи.** Дія формулює навігацію
мовою користувача: «Мені виповнилось 14», «У мене народилася дитина». Людина
впізнає себе, а не шукає юридичну категорію. Наші картки «Що сталося?» — той
самий патерн, але формулювання безособові («Загинув або помер
військовослужбовець»).

**1.2. Search-first головна.** Перший екран Дії — це велике поле пошуку з
прикладами запитів («Наприклад: відкрити ФОП»). У нас пошук захований на
сторінці «Корисна інформація».

**1.3. Один рядок «що робити» під кожною послугою.** Кожна картка послуги в
Дії має підказку наступного кроку: «Авторизуйтесь, заповніть форму та
підпишіть заяву». Знімає невизначеність до кліку.

**1.4. Проста мова + пастельна стриманість.** Білий фон, чорний текст, м'які
кольори, великий шрифт e-Ukraine, короткі анотації категорій. Жодного
канцеляриту. Наш сайт це вже наслідує, але тексти місцями щільніші, ніж у Дії.

**1.5. Канали підтримки внизу кожної сторінки.** Чат-боти Telegram / Viber /
Messenger + застосунок. У нас месенджери приховані, поки не задані контакти, —
правильно, але після заповнення конфігів їх варто зробити помітнішими.

З GOV.UK беремо: патерн **start page** (одна сторінка = один зрозумілий вхід у
процес із кнопкою «Почати»), **step-by-step navigation** для лінійних
процедур, принцип **«одна дія на екран»** для форм і правило писати заголовки
як завдання користувача, а не назви послуг.

## 2. Аудит поточного сайту

Методика: перевірка відрендереного HTML (25 маршрутів), код компонентів,
евристики Нільсена, WCAG 2.2 AA, порівняння з патернами Дія/GOV.UK.

**Що вже добре:** один H1 на сторінку; skip-link працює; семантичні заголовки;
формa без dark patterns; чесні формулювання без гарантій; захист чутливих
даних; reveal-анімації вимикаються через `prefers-reduced-motion`; блок
відгуків прихований, поки порожній; мобільна нижня CTA не перекриває контент.

Нижче — знахідки. Пріоритети: **P0** — критично для конверсії/довіри,
**P1** — важливо, **P2** — бажано, **P3** — коли дійдуть руки.

## 3. Порядок впровадження (пропозиція)

**Спринт 1 — конверсія і довіра (P0):**
F1 (tel-клавіатура) → T1 (сховати службові позначки на проді) → N1 (меню
«Ситуації») → F2 (окрема сторінка форми) → T2 (реальні дані команди — на боці
власника).

**Спринт 2 — навігація і контент (P1):**
N2 (крихти) → C1 (summary + зміст на ключовій сторінці) → F3–F5 (форма) →
T3 (позиція дисклеймера) → V1–V2 (піктограми сторінок, шрифт Fixel) → A1–A2.

**Спринт 3 — полірування (P2–P3):**
N3 (глобальний пошук) → C2–C4 → V3–V5 → A3–A5 → P1t → F6–F7.

Після кожного спринту: Lighthouse (Performance/A11y/SEO ≥ 90), axe-scan,
ручний прохід клавіатурою, тест на реальному телефоні.

---

## 4. Чого свідомо НЕ робимо (навіть якщо «так у всіх»)

Каруселі «популярних послуг» (є в Дії — але в нас 5 ситуацій, вони мають бути
видимі всі одразу); чат-бот з юридичними висновками; попапи «залиште телефон»;
лічильники і таймери; стокові фото Феміди/рукостискань; фото горя. Це
зафіксовано в ТЗ і docs/SENSITIVE_CLAIMS.md.
