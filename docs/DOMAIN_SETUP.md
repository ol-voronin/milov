# Підключення домену zastupa.com.ua: HOSTiQ + Vercel

Домен зареєстровано в HOSTiQ, сайт працює на Vercel. Пошта — на домені.

**Схема, яку налаштовуємо:**

```
        zastupa.com.ua  (реєстратор — HOSTiQ)
                 │
      NS: dns1/dns2.hostiq.ua  ← зоною керує HOSTiQ
                 │
    ┌────────────┼──────────────┐
    │            │              │
  A / CNAME     MX            SPF/DKIM/DMARC
    │            │              │
  Vercel      пошта          захист пошти
  (сайт)
```

**Чому саме так, а не NS на Vercel.** Якщо віддати неймсервери Vercel,
уся зона переїде туди, і MX-записи для пошти доведеться заводити заново
на його боці. Тримаючи зону в HOSTiQ, ви керуєте сайтом і поштою в
одному місці.

> ⚠️ **Не змішуйте неймсервери двох провайдерів.** Якщо в списку NS
> стоятимуть і `dns1.hostiq.ua`, і сервер Vercel — резолвери вибиратимуть
> випадковий, і сайт відкриватиметься приблизно через раз. Сертифікат
> теж не випуститься. Або всі NS від HOSTiQ, або всі від Vercel.

---

## Крок 1. Неймсервери на боці HOSTiQ

Панель клієнта HOSTiQ → бокове меню **«Мої домени»** → іконка **«Деталі»**
навпроти `zastupa.com.ua` → блок **«Неймсервери»**.

Поставте перемикач у положення:

- **«Встановити NS для керування DNS із HOSTiQ.ua без хостингу»** — якщо
  хостинг у HOSTiQ не використовуєте;
- **«Встановити NS віртуального хостингу від HOSTiQ.ua»** — якщо хостинг є
  (тоді DNS редагується не тут, а в cPanel).

Поля «Неймсервер 3–5» мають бути **порожні**. Збережіть і оновіть сторінку.

Під блоком «Неймсервери» з'явиться кнопка **«Керування DNS»**. Якщо її
немає — перемикач стоїть не в тому положенні.

---

## Крок 2. Додати домен у Vercel

Проєкт → **Settings → Domains → Add**. Додайте обидва:

- `zastupa.com.ua`
- `www.zastupa.com.ua`

Основним зробіть **без www**, а `www` хай редіректить на нього. Інакше
сайт існуватиме за двома адресами, і пошук рахуватиме це як дублікат.

Vercel покаже статус «Invalid Configuration» і **конкретні значення**
A-запису та CNAME. Не закривайте цю вкладку — значення знадобляться
в наступному кроці. Беріть саме те, що на екрані: адреси залежать від
проєкту й іноді змінюються.

---

## Крок 3. Записи для сайту в HOSTiQ

«Керування DNS» → порожній рядок унизу списку.

| Ім'я хоста | Тип | Адреса | Пріоритет |
|---|---|---|---|
| корінь — див. підказку вгорі сторінки | A | IP від Vercel | порожньо |
| `www` | CNAME | значення від Vercel | порожньо |

> **Пастка.** Поле «Ім'я хоста» для кореневого домену заповнюється
> по-різному в різних зонах: десь `@`, десь порожньо, десь повне ім'я.
> HOSTiQ показує правило саме для вашої зони вгорі сторінки «Керування
> DNS» — прочитайте перед заповненням.

**Перед додаванням видаліть наявні A і CNAME для кореня та `www`**, якщо
вони вже є: реєстратор зазвичай ставить їх на свою сторінку-заглушку, і
вони конфліктуватимуть. Видалення в HOSTiQ — очистити всі поля рядка й
натиснути «Зберегти зміни»; окремої кнопки видалення там немає.

**MX-записи не чіпайте.**

---

## Крок 4. Пошта на домені

Спочатку створіть скриньки у провайдера пошти, потім додайте його записи
тут же, в «Керуванні DNS».

Мінімальний набір адрес:

| Адреса | Навіщо |
|---|---|
| `info@zastupa.com.ua` | Загальна, вказується на сайті |
| `privacy@zastupa.com.ua` | **Обов'язкова.** Політика конфіденційності обіцяє контакт для запитів щодо персональних даних — ця адреса мусить працювати |
| особиста, на ваше ім'я | Листування у справах |

Провайдер дасть чотири типи записів. Заведіть **усі**:

| Тип | Навіщо |
|---|---|
| MX | Куди доставляти пошту. Без нього листи не приходять |
| SPF (TXT) | Хто має право слати від вашого імені |
| DKIM (TXT) | Підпис листів |
| DMARC (TXT) | Що робити з листами, які не пройшли перевірку |

Три останні не є формальністю. Без них частина листів осідає в спамі
мовчки — ви не дізнаєтесь, що родина не отримала відповіді.

Поле «Пріоритет» заповнюється **тільки** для MX (провайдер вкаже число,
зазвичай 10).

---

## Крок 5. Змінна середовища у Vercel

Settings → **Environment Variables**:

```
NEXT_PUBLIC_SITE_URL = https://zastupa.com.ua
```

Потім **Redeploy**. Без цього `sitemap.xml`, `robots.txt` і canonical
на всіх сторінках лишаться зі значенням за замовчуванням.

Заразом перевірте, що на місці змінні Telegram — інакше заявки з форми
нікуди не приходитимуть:

```
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
```

---

## Крок 6. Зачекати й перевірити

Поширення DNS — зазвичай 15–60 хвилин, іноді до кількох годин. Vercel сам
змінить статус домену на «Valid Configuration» і випустить сертифікат.
Натискати нічого не треба, купувати SSL — теж.

Що перевірити після:

- `https://zastupa.com.ua` відкривається із замочком;
- `https://www.zastupa.com.ua` редіректить на версію без www;
- `https://zastupa.com.ua/sitemap.xml` містить правильний домен;
- форма заявки надсилається і повідомлення приходить у Telegram;
- лист на `info@zastupa.com.ua` доходить.

## Якщо не працює

**Vercel тримає «Invalid Configuration» понад дві години.**
Найчастіше — не видалено старий A-запис на заглушку реєстратора, або
ім'я хоста для кореня заповнене не за правилом зони.

**Сертифікат не випускається, хоча DNS правильний.**
Подивіться, чи немає в зоні запису типу **CAA**. Він обмежує, який центр
сертифікації може видавати сертифікати для домену. Якщо CAA є і в ньому
не згадано `letsencrypt.org` — додайте його або видаліть запис.

**Сайт відкривається через раз.**
Змішані неймсервери. Поверніться до кроку 1 і приберіть чужі NS.

**Листи йдуть у спам.**
Не заведено SPF, DKIM або DMARC. Перевірити можна, надіславши лист на
будь-яку gmail-адресу й подивившись «Показати оригінал» — там видно
результат усіх трьох перевірок.

## Що оновити в коді після налаштування

У `src/config/site.ts` замінити заглушки на реальні адреси:

```ts
email: 'info@zastupa.com.ua',
privacyContact: 'privacy@zastupa.com.ua',
```

Телефон там теж поки заглушка (`+380000000000`).
